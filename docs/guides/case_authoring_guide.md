# 案例文档编写与沉淀指南 (Authoring Guide)

## 1. 案例撰写流程标准

为确保 Vanguard 平台内所有案例具有高度一致的专业度、可读性与结构性，案例文档编写遵循“四步递进法”：

```text
[1. 立项与问题界定] ➔ [2. 深度事实与数据推导] ➔ [3. 决策建议与提炼] ➔ [4. 静态产物规划]
```

---

## 2. 各阶段详细编写要点

### 2.1 第一阶段：立项与问题界定 (`01_overview.md`)
- **核心目的**：用清晰、客观的文字阐明本案例的核心驱动力。
- **必写要素**：
  - **业务痛点 / 研究诱因**：当前遇到了什么阻碍？为什么必须启动分析？
  - **边界与范围**：本案例明确解决哪些问题，明确不涉及哪些衍生话题。
  - **核心指标定位**：最终评估成败的具体基准是什么？

### 2.2 第二阶段：深度事实与数据推导 (`02_research.md`)
- **核心目的**：杜绝主观臆断，依靠客观数据、技术对比与逻辑推导构建分析底座。
- **推荐格式**：
  - **多方案矩阵表**：使用 Markdown 表格横向对比成本、性能、门槛、可维护性等。
  - **定量数据沉淀**：明确数据口径与实验/调研样本。
  - **因果关系梳理**：通过清晰的列表或 Mermaid 流程图展现推演链条。

### 2.3 第三阶段：决策建议与提炼 (`03_conclusion.md`)
- **核心目的**：从事实调研中萃取高价值洞察。
- **要求**：
  - 提炼出 1~3 条核心洞察（Key Takeaways），使用 Markdown 强调引用块展示。
  - 给出具备可操作性、有明确先后顺序的落地路线图。

### 2.4 第四阶段：静态产物呈现规划
- 在文档末尾规划好拟在静态网站中展示的：
  1. **Top 3~4 个核心 KPI 数据卡片**（如“成本削减 80%”、“响应加速 5 倍”等）；
  2. **1~2 处数据可视化图表**（如对比柱状图、趋势曲线）；
  3. **落地执行清单**。

---

## 3. 文档格式与排版规范

- **全中文沟通**：专业名词有公认中文名称的优先使用中文，专有名词（如 API、Git、JSON 等）保持标准英文书写。
- **标点与空格规范**：中文与英文字符/数字之间保留空格以提高视觉可读性（如 `在 2026 年启动项目` 而非 `在2026年启动项目`）。
- **结构化优先**：尽量少用冗长的大段叙述，善用列表项、表格、加粗重点和代码块呈现关键信息。
