# 01. 产品需求文档 (PRD) — Vanguard

## 1. 业务目标与背景
前线部署工程师（FBE）在客户现场调查、需求对接与访谈过程中，常面临以下挑战：
- **访谈记录零散**：存在现场录音、手机拍照、突发想法记录等多种数据源。
- **隐性需求难挖掘**：客户直说的诉求（显性需求）往往只是冰山一角，背后隐藏着系统控制权、组织管理阻力等隐性需求。
- **经验无法复用**：不同 FBE 收集到的行业特征与解决方案分散在个人笔记本中。

Vanguard 平台旨在通过 AI Agent 赋能 FBE，实现从多模态输入到结构化洞察报告的自动化沉淀。

---

## 2. 七维度需求分析框架

Agent 在分析客户访谈文本与素材时，将自动归类并挖掘以下七个维度的信息：

1. **功能性需求 (Functional)**：客户明确要求的具体系统功能或特性。
2. **痛点需求 (Pain Points)**：当前流程中引起低效、报错或不满的核心问题。
3. **目标需求 (Jobs-to-be-done)**：客户希望通过本项目达成的终极业务目标。
4. **隐性期望 (Latent Desires)**：未直接说出口但隐含在表达中的心理诉求（如安全性担忧、管理控制感）。
5. **情感需求 (Emotional)**：客户在决策过程中的焦虑感、信任感或安全感诉求。
6. **社会需求 (Social)**：项目成果在客户公司内部政治、同行竞争或上级汇报中的影响。
7. **约束条件 (Constraints)**：预算上限、上线合规要求、时间节点与硬件条件限制。

## 3. 用户故事 (User Stories)

- **US-1**：作为 FBE，我可以在访谈结束后，将录音文件与现场照片上传至 Vanguard 平台。
- **US-2**：作为 FBE，我希望 Agent 在 3 分钟内自动转录录音并结合照片生成初步的显性/隐性需求矩阵。
- **US-3**：作为 FBE，我可以检索团队知识库，查看类似客户的历史洞察与应对策略。
- **US-4**：作为 FBE，我可以将高质量的访谈洞察一键贡献至团队知识库，供全团队 Agent 共享调用。
- **US-5 (Active Operator)**：作为 FBE，我希望 Vanguard 能帮我生成客户系统配置文件的修改补丁 (Diff 代码块)，并允许我在 UI 界面上审查和一键复制，而不需要手动编写代码。
- **US-6 (Active Operator)**：作为 FBE，我希望大模型在诊断报错时，能主动调用内置的诊断工具（如 ping、curl、日志过滤），通过接口验证它的猜想，而不是仅给出理论分析。
