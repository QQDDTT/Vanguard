# Vanguard 平台化总体架构与设计方针

## 1. 平台演进背景与核心定位

### 1.1 背景转变
传统的企业级或分析型系统通常采用重型服务端（Server-Side）架构，依赖云端容器（如 Cloud Run）、分布式 API 网关、关系型/向量数据库等。这种架构在本地单兵作战、轻量化知识沉淀和敏捷案例交付场景下面临以下痛点：
- **运维负担沉重**：本地依赖多语言运行时（Python/Node/Rust）及环境配置。
- **资产流动性差**：数据散落在云端数据库与专有存储中，难以直接通过文件系统版本化备份与直观阅读。
- **交付链路冗长**：从调研到产物往往需要前后端联动编译部署。

### 1.2 核心定位
**Vanguard** 确立了全新的**“纯本地文档驱动 + 案例静态化产物”**平台化方针：
- **无 Server 架构 (Serverless / No-Server)**：彻底摒弃本地与远端常驻 Server 进程，无需启动任何后端服务。
- **文档资产中心 (Document as Source of Truth)**：所有知识、调研、案例分析以结构化 Markdown 文件存放在本地文件系统，通过 Git 实现全量可追溯的版本管理。
- **案例定制静态产物 (Case-Driven Static Artifacts)**：针对具体业务或研究案例，按需生成自包含、即开即用的高水准纯静态网站（HTML/CSS/JS），无需任何运行时即可本地双击浏览或快速分发。
- **零环境依赖 (Zero-Runtime Constraint)**：严格执行不依赖 Node.js/Python 的原则，自动化能力完全依托 Windows 原生 PowerShell 与批处理脚本。

## 2. 核心设计哲学

```
           ┌──────────────────────────────────────────────┐
           │            Vanguard 核心设计哲学              │
           └──────────────────────┬───────────────────────┘
                                  │
         ┌────────────────────────┼────────────────────────┐
         ▼                        ▼                        ▼
  【本地优先 Local-First】  【资产自包含 Self-Contained】  【原生轻量 Zero-Runtime】
   文件系统为最终持久源       产物离线可运行、即开即用        仅依赖原生浏览器与 PowerShell
```

1. **本地优先 (Local-First)**：所有数据资产保存在本地硬盘中，无需网络也能完整进行知识沉淀、文档编辑与产物查阅。
2. **资产自包含 (Self-Contained Artifacts)**：每个案例的静态网站产物均将结构、样式、逻辑与可视化组件封装为独立的纯前端文件，具备极佳的便携性。
3. **原生轻量 (Zero-Runtime & Native)**：杜绝复杂的打包编译链，确保任何人拿到产物后，通过系统自带浏览器即可直接运行。

## 3. 平台四层架构模型

平台整体逻辑划分为四层体系：

```mermaid
graph TD
    subgraph Layer1 [1. 数据与文档管理层 Data & Knowledge Layer]
        A1[通用知识库 /docs/guides]
        A2[案例分析档案 /cases/{case_id}/docs]
        A3[结构化元数据 metadata.json]
    end

    subgraph Layer2 [2. 平台工作流与管线层 Workflow Pipeline Layer]
        B1[立项与脚手架初始化] --> B2[研究调研与结构化提取]
        B2 --> B3[内容提炼与评审]
        B3 --> B4[静态产物映射与组装]
    end

    subgraph Layer3 [3. 静态产物生成规范层 Static Artifacts Layer]
        C1[Vanilla HTML5 语义架构]
        C2[精美现代化 CSS 视觉系统]
        C3[轻量无依赖原生 JS / SVG 图表]
    end

    subgraph Layer4 [4. 自动化与支撑工具层 Native Tooling Layer]
        D1[PowerShell 自动化脚手架]
        D2[本地索引构建与搜索脚本]
        D3[静态网站健康度与资源校验]
    end

    Layer1 --> Layer2
    Layer2 --> Layer3
    Layer4 -.-> Layer1
    Layer4 -.-> Layer2
    Layer4 -.-> Layer3
```

### 3.1 数据与文档管理层
- **规范目录**：通过统一的目录规范隔离通用知识与案例专属档案。
- **元数据标注**：利用统一的 Frontmatter 或 `metadata.json` 记录案例标签、更新日期、分类维度、核心结论。

### 3.2 平台工作流与管线层
- 建立从“问题定义”到“深度调研”，再到“核心结论沉淀”，最后到“静态网页生成与归档”的闭环流转标准。

### 3.3 静态产物生成规范层
- 提供符合现代视觉标准（深色/浅色、响应式、精致排版、SVG 数据图表）的原生静态模板库。
- 确保零外部构建依赖，直接在浏览器中解析渲染。

### 3.4 自动化与支撑工具层
- 提供一套纯 Windows 原生（PowerShell）的辅助工具集，用于案例初始化、静态资源打包、全量案例索引自动汇总等任务。

## 4. 核心术语与实体定义

| 术语 | 英文标识 | 说明 |
| :--- | :--- | :--- |
| **案例** | `Case` | 具体的业务调研、技术评测、策略分析单元，具备独立目录与完整生命周期。 |
| **知识单元** | `Knowledge Unit` | 沉淀于 `docs/` 或案例 `docs/` 内的模块化 Markdown 文本、数据表或流程图。 |
| **静态产物** | `Static Artifact` | 针对特定案例生成的自包含前端网站目录（包含 `index.html`、`styles.css`、`app.js` 等）。 |
| **脚手架** | `Scaffold` | 用于在本地迅速生成标准案例骨架目录与元数据文件的 PowerShell 脚本。 |
| **元数据** | `Metadata` | 描述案例 ID、标题、所属领域、标签、状态及产物发布路径的结构化描述。 |
